# Библиотека Миши

Веб-каталог: карточки и таблица, поиск, фильтры, редактирование, обложки, любимые книги, очередь проверки, полные JSON-копии.

## Разработка и публикация

- Код: https://github.com/NikitaZhilin/book_NZMZ, ветка main.
- START_AUTO_PUBLISH.cmd запускает наблюдение за кодом, STOP_AUTO_PUBLISH.cmd останавливает.
- После 12 секунд без изменений выполняются Python-тесты и проверка JavaScript. Только успешная версия коммитится и отправляется в GitHub.
- GitHub Actions повторяет проверки. Сервер раз в минуту проверяет main и устанавливает только точный SHA с успешным workflow. SSH-ключи GitHub и правила sudo не используются.
- Если тесты не проходят, исправьте код; следующая стабильная версия проверяется снова.
- Перед ручными git commit/pull/merge остановите наблюдатель. Журнал: .local/auto-publish.log.
- Без доступа в интернет отправка повторяется каждые 30 секунд. История не перезаписывается.

## Данные

Каталог и обложки не находятся в публичном GitHub. На сервере они хранятся в /var/lib/book-nzmz/library.json. Предыдущая версия и ежедневные резервные копии хранятся отдельно от кода. Обновления приложения не перезаписывают библиотеку. Кнопка «Скачать копию» сохраняет пользовательскую копию со всеми обложками.

## Техническая основа

FastAPI + Uvicorn, один процесс, файловый каталог с атомарной записью и контролем версии. Caddy обеспечивает HTTPS. По текущему решению владельца сайт открыт без пароля, включая редактирование каталога. Сервис работает от отдельного непривилегированного пользователя. Это серверная версия прототипа: PostgreSQL и Telegram-бот остаются следующими этапами.

Для локальной разработки: установить Python 3.12+, создать .venv, установить requirements-dev.txt. Запуск: python -m uvicorn app.main:app --host 127.0.0.1 --port 8769. PUBLIC_ORIGIN=http://127.0.0.1:8769, MISHA_LIBRARY_DATA указывает отдельную папку данных.
Проверки: python -m unittest discover -s tests -v; node --check prototype/app.js.

В проекте также сохранён прежний локальный запуск prototype/START_LIBRARY.cmd. Локальные и серверные данные независимы; перенос выполняется через скачанную копию.

Автоматическая публикация запускается также при входе в Windows. Компьютер должен быть включён, а папка проекта доступна. Каталог редактируется на сайте независимо от локального наблюдателя.

## Выгрузка, редактирование и восстановление
- «Полная копия»: свежий JSON со всеми книгами, обложками и исходными метаданными.
- «Для ИИ · JSON»: объект с массивом books, стабильными id и baseRevision; без обложек и истории. Инструкция включена в файл. quantity — физические экземпляры. Сохраните id существующих книг; для новой книги уберите id. Отсутствующее поле сохраняется, пустая строка явно очищает его. Год и страницы — строки.
- «Импорт и сверка»: показывает изменения полей до записи, по умолчанию не удаляет отсутствующие книги. Файл для ИИ из устаревшей версии блокируется. Возможные дубли требуют сверки id. Сырой массив книг также поддерживается, но не содержит проверки давности выгрузки.
- Для отката скачайте нужную версию из «Истории копий», импортируйте её и включите полное восстановление. Предыдущая версия сохраняется перед записью, поэтому откат тоже обратим.
- Перед каждой записью сервер сохраняет неизменяемую JSON-версию в /var/lib/book-nzmz/backups. Эти версии автоматически не удаляются; нужно следить за свободным местом. При ошибке создания копии сохранение каталога отменяется. Ежедневные копии хранятся 30 дней.
- Наблюдатель на Windows каждые 15 минут скачивает изменившийся каталог в .local/server-backups. Копии не отправляются в GitHub и автоматически не удаляются. Компьютер, интернет и наблюдатель должны работать. Ошибки записываются в .local/auto-publish.log.
- Для защиты от потери одновременно компьютера и сервера дополнительно храните полную копию на независимом носителе/в своём облаке. Абсолютной гарантии отсутствия потерь нет.
